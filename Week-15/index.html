Requirements ≠ devices

“200 students need stable Wi-Fi” is a requirement. “Install six access points” is a proposed solution that still needs testing.

Design ≠ validation

A network drawing can look correct while a link remains overloaded. Validate against measurable targets.

Management ≠ repair only

Network management includes monitoring, configuration, fault response, performance planning and documentation.

Q1 · APPLY

Design a small university department network

The department has 50 wired desktops, 30 wireless laptops, a file server and Internet access. Identify the main network components and explain how users reach the file server and Internet.

Reveal model answer

Use access switches for wired desktops, wireless access points for laptops, an appropriate core/distribution connection, a router/firewall for Internet access, and a file server on a protected network segment. The switches and access points provide local connectivity; traffic reaches the server through the LAN, while Internet-bound traffic passes through the firewall/router. IP addressing, DHCP and DNS support device connectivity and access to services.

Q2 · ANALYZE / EVALUATE

Assess an overloaded network design

A campus uplink provides 500 Mbps. During peak use, 160 active users consume 4 Mbps each on average. Calculate expected demand and utilization; explain the problem and propose two improvements.

Reveal model answer

Demand = 160 × 4 = 640 Mbps. Utilization relative to the available link is 640/500 × 100 = 128%, meaning demand exceeds link capacity; users may experience congestion, delay and drops. Improvements include upgrading the uplink, traffic prioritization for critical applications, capacity planning using measured peaks, and reducing unnecessary traffic. The numbers represent a simplified planning model.

Q3 · CREATE / JUSTIFY

Improve network reliability and management

A campus relies on one central switch. When it fails, the whole campus disconnects. Propose a better architecture and a basic monitoring and recovery plan. Justify your choices.

Reveal model answer

Identify the single core switch as a single point of failure. Where justified, provide redundant core/distribution equipment and alternative links with correctly configured loop prevention or routing/failover. Add configuration backups, a change-management procedure, device and interface monitoring, threshold alerts, documentation, and regular recovery tests. This reduces outage risk and makes faults easier to locate. Redundancy alone does not guarantee resilience unless failover is tested.
