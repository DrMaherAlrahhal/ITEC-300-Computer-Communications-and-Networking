01 · Put the message in a frame

Why doesn't a network send only “HELLO”?

On a local link, the data link layer organizes data into a frame. A frame carries information needed for local delivery and checking for errors.

A → B
PayloadYour message
HELLO

Discover: The payload contains the message. The header helps identify the link-layer endpoints. The trailer can contain an error-detection value.

What does each part do?

Header

Information used to deliver the frame on the local link, such as source and destination MAC addresses in Ethernet.

Payload

The data being carried. For our example, the text you entered is the payload.

Trailer

In Ethernet, the frame check sequence (FCS) helps detect whether the frame was damaged during transmission.

The builder uses friendly device names and an educational CRC-8 value. Real Ethernet uses MAC addresses and a CRC-32 FCS; this is not a byte-for-byte Ethernet frame.

02 · Disturb the signal

What is noise? What is a bit error?

Noise is unwanted disturbance added to a signal. If the receiver reads a 1 as a 0, or a 0 as a 1, a bit error has occurred.

Turn up the noise

Illustrative waveform only. Increasing noise does not guarantee a bit error, but it can make a signal harder to read correctly.

Three useful terms

Noise / interference

Unwanted energy disturbs the communication signal. Example: nearby electrical equipment affects copper wiring.

Single-bit error

One bit changes during transmission: 1011 → 1001.

Burst error

Several bits are affected within a span of transmitted bits.

Important: A weak signal (attenuation) and noise are different problems, but both can make reception less reliable.
03 · Catch the error yourself

Can the receiver tell that a bit changed?

The sender adds redundant check bits. The receiver checks them after transmission. Try flipping one or two bits to see the difference between simple parity and CRC.

Interactive bit-flip laboratory

Original 8-bit data: 10110010. Click any blue bit to change it. The check bits stay as originally transmitted.

Even parity

A simple error check

The sender adds one parity bit so the total number of 1s is even.

Parity detects any odd number of bit flips, but can miss an even number of flips.

CRC-8 demonstration

A stronger error check

The sender computes a CRC remainder. The receiver checks the received data using the same rule.

This is a small educational CRC-8 using generator 100000111, not the Ethernet CRC-32 algorithm.

Key discovery: Error detection tells us something may be wrong. It does not automatically tell us the original bit values or repair them.

Parity

Very simple: one extra bit. Useful for understanding error detection, but limited.

Checksum

Combines data values into a check value. The receiver compares the result to detect many errors.

CRC

Uses polynomial division on bits. Widely used for detecting accidental transmission errors.

04 · Recover from an error

What happens after a damaged frame is detected?

Error control is the response to damaged or missing data. One common approach is to ask for a new copy using acknowledgments and retransmissions.

⇄
ReceiverChecks frame and replies
Ready to start.

Understand the words

ACK (acknowledgment)

A message indicating successful reception of the frame.

Timeout

The sender waits for a response. If it does not arrive in time, the sender may retransmit.

Retransmission (ARQ)

The sender sends the frame again after a loss or error. Sequence numbers can help the receiver recognize duplicates.

Forward error correction (FEC)

Extra information may allow a receiver to correct certain errors without asking for retransmission.

Compare: Parity / CRC = detect. ARQ = recover by retransmission. FEC = correct certain errors using redundancy.
